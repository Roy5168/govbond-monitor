# 公債市場觀測（台灣中央政府公債買賣斷）

單檔、離線、可自行更新的公債買賣斷觀測工具。

## 版本

目前 **V1.3.3**（2026-11-05）。版號寫在 `template.html` 的 script 開頭（`APP_VERSION`／`APP_DATE`／`CHANGELOG`），顯示在報頭、週報列印頁右上角、「資料說明與檢核」分頁的版本紀錄。

抓的檔案是櫃買買賣斷日檔：

- 營業處所 `BDdcs001.YYYYMMDD-C.xls`（只取 `BDdcs01a` 工作表，`BDdcs01b` 是附條件交易，不能混進來）
- 等殖成交系統 `BDdys01a.YYYYMMDD-C.xls`

網址規則 `https://www.tpex.org.tw/storage/bond_zone/tradeinfo/govbond/{YYYY}/{YYYYMM}/{檔名}`。
人工查閱頁面：[等殖成交系統](https://www.tpex.org.tw/zh-tw/bond/info/statistics-gb/day/ebts.html)、[營業處所](https://www.tpex.org.tw/zh-tw/bond/info/statistics-gb/day/otc.html)。

只留券號符合 `A` ＋ 5 碼（可含 R 尾碼）的中央政府公債，處所檔另外只取幣別 TWD 的列。

抓取遇到暫時性錯誤（5xx、逾時）會自動重試 3 次；重試後仍失敗的日期會被單獨列出並提醒重跑，**不會**被誤當成休市而在資料裡留下看不出來的缺口。

執行後有三種「沒有新資料」，訊息會分開講：**週末／休市**（沒有日檔）、**尚未發布**（同樣沒有日檔，晚點再跑）、**有日檔但公債 0 筆**（當天有交易，只是沒有公債買賣斷成交——日檔本身涵蓋公司債與外幣債）。例如 2026-08-31 兩個市場都有日檔，但只成交了台化與星宇航的公司債，公債一筆都沒有。同一天重抓會覆蓋原值，鍵是（交易日, 券號, 市場別），不會產生重複資料。

**單位一律轉成同一組再存**：殖利率與百元價用百分比（1.205 表示 1.205%）、成交面額與金額用億元。處所日檔的面額是「元」、等殖日檔是「億」，這一步就是最容易出錯的地方，已經對過帳：同一天的日檔與 GPT 彙整檔逐欄比對零差異。

打開 `公債市場觀測.html` →「匯出／匯入」分頁：

## 官方發行日（年期判定的依據）

```bash
python3 ~/Documents/BondMarket/parse_issues.py                  # 抓官方 CSV（update.py 每次也會自動抓）
python3 ~/Documents/BondMarket/parse_issues.py 標售概況表.pdf    # 沒網路時改吃 PDF
```

來源是中央銀行開放資料的「中央公債標售概況表」：
`https://www.cbc.gov.tw/public/data/OpenData/國庫局/債券科/Bond-Auction-Results.csv`（[政府資料開放平臺](https://data.gov.tw/dataset/7234)），每有新券標售就更新，欄位是期別、發行日期、年期。`update.py` 每次執行都會順手更新一次（`--no-issues` 可跳過），所以新券一發行就有官方發行日，不會停在推估。

**別再只靠 PDF 快照**：PDF 是人工下載的靜態檔，一旦落後，新券就會退回推估——而推估對「發行前交易」是失效的（見下）。

券號對照：`A` ＋ 民國年後兩碼 ＋ 類別（甲=1、乙=2）＋ 序號兩碼，例如 115甲6 → `A15106`。標售表上標 `※` 的是**增額發行**，不會改首次發行日，只記錄最近一次增額日期；`Δ`／`△` 是可分割公債（105 年起停發）。券號尾碼 `R` 的發行前交易沿用本券的發行資料。

**官方值優先，查不到才推估**：只有早於資料起始年度（94 年度）的老券會回退到推估。目前 158 檔中 **156 檔用官方值**，2 檔推估（`A90105`／`A93106`）。

**發行前交易會讓推估失效**：券還沒發行時，櫃買以名目年期報價，剩餘年限每天都固定不動。`A15108` 在 2026-07-23 至 09-01 的成交，剩餘年限全部是 5.00，到 09-09 才變成 4.98 開始倒數。用「到期日＝交易日＋剩餘年限」去推，發行日會跟著交易日一直往後飄（曾經從 08-13 飄到 09-01），指標券也會提早換手。官方發行日是 **2026-09-04**，5 年期指標券就該在那天才從 `A15101` 換成 `A15108`。

**「發行前」是看日期，不是看券號**：`A15108` 沒有 R 尾碼，但發行日之前的成交就是發行前交易。介面依「當天是否已過發行日」判定，這些成交不會被當成指標券，也不會進參考曲線的節點。

推估法與官方資料實測對照：**年期 102 檔全數相符**，發行日誤差中位數 2 天、最大 4 天——所以退回推估時判定仍然可靠。

## 冷門券怎麼判定

**冷門券＝非現行流通的指標債券**。指標券是 2／5／10／20／30 年期中，各天期最近發行、發行日已到、且發行未滿 3 年的那一檔；其餘（卸任的舊指標券、老券）都是冷門券。指標券會隨新券發行換手，所以每一天的判定都以當天為準——一月的 10 年期指標券到八月可能已經是冷門券。

年期與發行日以上面的官方資料為準；**只有查不到時才推估**（作法如下）：由券號（`A`＋民國年 2 碼＋類別 1 碼＋序號 2 碼，尾碼 `R` 為發行前交易）取得發行年度，由當日剩餘年限推回到期日，年期取**不超過推估區間的最大標準年期**（2／3／5／7／10／15／20／30），發行日＝到期日−年期。

這裡的推估區間是「到期日 − 發行**年度起點**」，所以必然等於真實年期加上發行當年已過的比例（實測 110 檔券落在 +0.02～+0.89，沒有一檔超過 1.0）。因此要取「不超過它的最大標準年期」，取最接近的會把 115央債乙3（區間 2.54）誤判成 3 年期。3／7／15 年期可以被正確辨識，但不列入指標券候選（`BENCH_TENORS` 仍是 2／5／10／20／30）。台債各年期相隔夠遠，這個推估足以判定指標券；2026-08-21 推得的結果是 2Y A15203、5Y A15108、10Y A15106、20Y A15107、30Y A15105，與實際指標券相符。

發行前交易不列為現行指標券，也不進參考曲線節點。判定方式有兩種：券號帶 `R`，或**當天還沒到發行日**（`A15108` 屬於後者）。

**發行日的「推估」標示是動態的**：已發行的券直接顯示日期，不再標「推估」（資料來源仍可在「資料說明與檢核」分頁與冷門券 CSV 的「發行日來源」欄查到）；只有還沒到發行日的券才會標「預計發行」或「尚未發行」，因為那時的日期本來就是預告值。

## 週報分頁（05）

彙整一週（週一～週五）的公債市場，預設顯示**最近一個完整週**（週五已過，或資料已含週五）；可用「前一週／後一週」往回翻。

**列印版（A4 直式，固定 2 頁）**：按「列印／存成 PDF」或在週報分頁直接 ⌘P，會切成專用版面——報頭改為白底週報抬頭（週次、市場別、資料日），隱藏按鈕與說明文字，改在文末印一段「註」；圖表以 A4 紙寬重畫；字級（V1.2.1，使用者兩度要求放大後）：摘要 11.5pt、重點數字 20pt、表格 10.3pt、表頭 8.8pt、圖上文字約 9pt、附註 8.6pt，列印時一律淺色。第 1 頁：摘要、重點數字、指標券變動（兩圖並排＋表）、每日成交面額；第 2 頁：非指標券年限分布圖與明細表（超過 24 檔自動壓縮列高、縮小分布圖；目前只有 36 檔的那一週會再整頁縮 2%）。字放大後欄寬不夠，列印版的表格用較短寫法：`sortableTable` 的欄位可帶 `pl`（列印欄名）、`pf`（列印格式）、`np`（不印）；日期與該週同年只印月/日。網址加 `#print-week:2026-09-07` 可直接開某週的列印版。

**分頁不交給瀏覽器**（2026-10-08 改）：每頁是一張固定大小的 `.sheet`（190mm × 最高 275mm、`overflow:hidden`、`break-after:page`），裡面的 `.sheet-in` 先用 `zoom:3` 放大排版、再用 `transform:scale(1/3)` 縮回。`.sheet` 另加 `contain:size`，讓它對分頁演算法是不可分割的一塊——否則 Safari 會在放大後的內部座標再套一次分頁，在每頁 1/3、2/3 處把表格列往下推，文末附註被切掉（只用 `overflow` 擋不住）。`fitSheets()` 會依內容定每張紙的高度，內容超過一頁或超出紙寬時等比例再縮，所以永遠是 2 頁、不會有欄位被切掉。

為什麼要這樣：瀏覽器的「最小字級」設定（Safari 進階設定的「永不使用小於 N 的字體大小」，Chrome 也有）會把 7pt 的表格字硬撐到 N px。使用者的 Safari 設 12，表格字變 9pt、表格超出紙寬，Safari 再把整頁縮到 88%，結果右側留白、下半部圖表被擠到第 2 頁、明細表突出卡片（共 3 頁）。放大 3 倍後最小的字也有 24px，高於 Safari 的最大選項。圖上的字另外處理：Safari 對 SVG 文字是看「最後畫在螢幕上的大小」套最小字級，所以列印時 `E('text')` 把字級放大 3 倍再用 `transform` 縮回，並加 `text-rendering:geometricPrecision`（WebKit 這時才只看指定字級）。

限制：Chrome 的最小字級是在 zoom 之前套用，這招對 Chrome 無效；Chrome 若自訂了最小字級，字仍會變大，`fitSheets()` 會把整頁等比例縮小以免切欄（仍是 2 頁）。Chrome 預設沒有最小字級，`weekly_pdf.py` 又用全新設定檔，所以不受影響。

驗證方法：`tools/wkprint.swift`（先 `swiftc -O tools/wkprint.swift -o wkprint` 編譯；用法 `wkprint "公債市場觀測.html#print-week:2026-09-28" out.pdf 12`，最後一個參數是最小字級）（WKWebView＋`NSPrintOperation`，與 Safari 同一套列印流程，可指定 `minimumFontSize`）把全部 91 週在最小字級 0／12／24 各印一次，全數 2 頁，三種設定下每個字的位置完全相同；另用 headless Chrome 逐週印，同樣全數 2 頁、無超出版心。

## 設計重點（為什麼長這樣）

- **冷門券沒有時間序列可看**：目前 158 檔券裡有 90 檔在 20 個月內成交 ≤10 天，畫傳統折線只會得到一堆斷點。
- 所以核心是**參考曲線＋利差**：取「回溯期間內每檔券最近一次成交」當節點，依剩餘年限線性內插成一條曲線，個券每一筆成交都換算成「對曲線利差（bp）」，稀疏散點因此變成可比較的訊號。
- 算某券利差時**排除該券自身**的節點，避免自我對照；剩餘年限落在節點範圍外時不外插，利差留白。
- 每日成交券數中位數只有 6 檔，所以回溯期間預設 10 個交易日。
- 「冷門券清單篩選」只是清單的輔助篩選（期間成交日數 ≤ N），不是冷門券的定義。
- 參考曲線的節點**排除發行前交易（R 券）**，相近年限併點時位置與殖利率都用成交面額加權。
- 利差與曲線水準的快取都把回溯期間編進 key，改期間會立刻重算（曾經漏掉，導致圖已更新但表格仍是舊值）。
- 個券頁的灰色參考曲線與下方利差圖是**同一套計算**：都排除該券自身的節點，並用該券在當日的剩餘年限（沒成交的日子由最近一次成交往回推算）。
- 匯入的 `.xlsx`／`.json` 一律當成不可信：兩種格式走同一道驗證（日期遞增、索引範圍、數值落在公債日檔的合理區間、市場別白名單、筆數上限），字串清掉標記符號，驗證不過整份退回。
- **匯入檔宣稱的統計與檢核一律不採信**：交易日數、券數、面額、檢核結果全部由資料本身重算，並強制標示「瀏覽器匯入」，避免有人做一份「檢核 OK、來源是櫃買」的假檔。
- 匯入時同一天、同一券、同一市場的重複列只留最後一筆（與 `bonddata.py` 的合併規則一致），不會重複累加面額；面額 ≤0、數值壞掉、非中央政府公債的列會被略過並在畫面上回報筆數，不會因為一列壞資料就整份匯入失敗。
- 匯入檔 `bonds` 裡的衍生欄位（剩餘年限、存續期間、面額、成交日數、首末日、年期、發行日、發行前旗標、類別）**一律不採信**，全部由 `recs` 與券號重算；券號必須符合 `A\d{5}R?` 且不得重複，`markets` 必須完全等於 `['營業處所','等殖成交系統']`（順序也要對），日期必須是真實存在的日期（`2026-02-31` 會被擋下）。
- xlsx 只解壓實際需要的 4 個檔案，並限制項目數、單檔與總解壓容量（防 zip bomb）；檔案本身也有大小上限。
- 產生 HTML 時會依內嵌後的 script 內容算 SHA-256，寫進 `Content-Security-Policy`：`default-src 'none'`、只允許那段自己的 script、`connect-src 'none'`。（`frame-ancestors` 只有 HTTP 標頭才生效，放在 meta 會被忽略，所以沒放；若日後要放上網站，請在伺服器加 `frame-ancestors 'none'` 與 `X-Frame-Options: DENY`。）就算未來哪裡漏掉跳脫，插入的 inline handler 也不會執行。
- 所有 CSV（含「原始明細」）都套用目前的市場別篩選（以目前資料為例：合併 3,638 筆、營業處所 1,288 筆、等殖成交系統 2,350 筆）。
- 匯出的 CSV：真正的數值直接輸出，字串只要以 `=`、`+`、`-`、`@`、Tab、CR 開頭就加前置單引號（`-1+HYPERLINK(...)` 這種偽裝成負數的字串也擋得住）。
- 熱區圖（券 × 交易日）用來一眼看出哪幾檔是死水。
- 成交筆數只有營業處所揭露，等殖成交系統日檔沒有，介面一律標示為「營業處所成交筆數」。
- 券號帶 R（增額發行）視為不同標的分列。
- 冷門券雷達的兩張表（清單與近期成交）欄位一致：券號｜名稱｜天期｜剩餘｜成交日數｜最近成交｜成交面額(億)｜最近殖利率｜對曲線(bp)。「成交面額」是**最近那一天的成交面額**，不是期間累計；期間累計仍保留在冷門券 CSV 的最後一欄。
- 當日散布圖的橫軸可選「線性刻度（等距年限）」或「非線性刻度（√年）」。非線性刻度**只改刻度間距、不改任何數值，也沒有平滑或配適**（殖利率、參考曲線、利差、表格、CSV 在兩種刻度下完全相同），目的是拉開高度集中的短天期：近 10 個交易日出現的券有 39% 剩餘年限 <2 年、76% <5 年，線性刻度下 0–2 年只佔畫面寬約 10%，非線性刻度可拉到約 32%。要判讀期限結構的形狀（陡平、曲度）請用線性刻度。（介面用「非線性刻度」而不寫「平方根」，是使用者偏好；數學上就是 √年，與「對數刻度」同類概念，切忌講成「平滑化」——那是對資料動手，本工具沒有做。）
- 天期走勢的殖利率圖叫「各天期成交殖利率」，上方可**個別勾選天期**（2Y／5Y／10Y／20Y／30Y，按鈕帶對應顏色點；「全部」一鍵還原）。選取會同時作用在圖、圖例、涵蓋率、各天期期間統計表與 CSV 匯出（檔名帶分組方式與天期，例如 `公債_天期日序列_年限區間_10Y_3M_20260907.csv`）；每個天期的顏色固定，不會因為篩選而重新配色。
- 天期走勢有兩種分組：**剩餘年限區間**（涵蓋期間成交面額約 41%）與**現行指標券**（on-the-run 序列，約 17%）。圖上會直接標出目前分組涵蓋多少成交面額——台債成交高度集中在剩餘 0–2 年，那段不落在任何天期區間內，這張圖本來就不是全市場。
- 每日成交面額圖疊了一條**月平均線**（該月每日成交面額的平均，以整個月的資料計算，不受目前顯示期間裁切；與長條同一個 Y 軸、同一個單位，沒有第二座標軸）。滑鼠停在任一天會同時顯示該月平均、成交日數與月合計。
- 天期走勢可切期間：3M／6M／YTD／1Y／全部。切換會同時作用在殖利率圖、每日成交面額圖、各天期期間統計表與該頁的 CSV 匯出（檔名帶期間標記，例如 `公債_天期日序列_3M_20260828.csv`）。
- 每日總覽由上而下是「日期／KPI → 當日成交明細 → 當日殖利率散布與參考曲線」：先看表、再看圖。
- 個券檢視由上而下是「殖利率 vs 參考曲線 → 成交面額 → 對曲線利差 → 成交紀錄」：先看價量，再看利差。
- 個券檢視的券別下拉選單依**發行日由新到舊**排列（選項上直接標出發行日），搜尋後仍維持同樣的順序。
- 每日總覽的日期改用**小月曆**選（按日期按鈕展開）：深色粗體＋圓點＝當日有公債成交、斜紋＝有交易日檔但（依目前市場別）無公債成交、淡色＝週末／休市／不在資料範圍；標題會顯示該月成交日數。« › 可翻年翻月，鍵盤方向鍵移動、Enter 選取、PageUp／PageDown 翻月、Esc 關閉。
- 卡片有進場動畫（`animation … both`），瀏覽器會為每張卡片各自建立堆疊層，卡片內浮層的 `z-index` 出不了卡片；所以月曆開啟時要把所在卡片加 `.raise`（z-index 50）整張抬高，關閉時移除，否則會被下一張卡片蓋掉一半。
- （舊的下拉選單已移除）日期按鈕會把「目前市場別下沒有成交」的日子標成「（無成交）」；這個標記必須在 `rebuild()` 算完 `byDate` 之後才產生（曾經在算完之前就建選單，導致剛開啟時所有日期、包括明明有成交的最新一天都被標成無成交）。
- 表格可用鍵盤操作：欄位標題與可點選的列都能 Tab 聚焦、按 Enter 排序或跳到該券。表格（當日成交明細、冷門券清單、個券成交紀錄）點欄位標題即可排序，數值欄第一下是由大到小，文字欄是由小到大；空值一律沉底。
- 英數與數字用 Times New Roman，中文用蘋方；只有終端機指令區塊維持等寬字體。

## 已知限制

- 參考曲線是市場成交點的內插，不是官方殖利率曲線。
- 網頁匯入 `.xlsx` 需要瀏覽器支援 `DecompressionStream`（Safari 16.4+／Chrome 80+）。
- 「成交面額加權平均殖利率」跨券跨市場加總，會受券別組合影響，只能當粗略指標。
- `update.py` 需要 `xlrd`（讀舊版 .xls）；目前環境已安裝 2.0.2。

## 櫃買網站 SSL 憑證錯誤（2026-09-14 修）

**症狀**：`update.py` 每個檔都 `CERTIFICATE_VERIFY_FAILED: unable to get local issuer certificate`，
重試後仍失敗。**原因在櫃買端**：www.tpex.org.tw 於 2026-09-07 換發憑證後，伺服器只送網站憑證、
漏送中間憑證「TWCA SSL Certification Authority」（`openssl s_client` 顯示 Verify return code 21）。
瀏覽器會自動補抓，所以網頁看起來正常；Python、curl 都會失敗，執行「Install Certificates」也沒用。

**修正**：中間憑證放在 `certs/TWCA_SSL_CA_2023.pem`（官方來源 http://sslserver.twca.com.tw/cacert/Cyber_SSL_2023.crt，
SHA-256 01:AF:23:24:…:E5:31，有效至 2033-02-23），`update.py` 建 `SSL_CTX` 時加入驗證憑證串，
仍完整驗證到系統信任的 TWCA CYBER Root CA（不是關閉驗證）。
若日後又出現憑證錯誤：`echo | openssl s_client -connect www.tpex.org.tw:443 -showcerts` 看簽發者，
從網站憑證的 Authority Information Access 網址下載新的中間憑證替換。
